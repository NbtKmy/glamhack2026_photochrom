# Photochrom Colours — 設計

日付: 2026-11-13 / 期限: GLAMhack 2026 発表（2026-11-14）

## 目的と背景

チューリッヒ中央図書館（ZB）の Photochrom コレクションから色の特徴量を取り出し、次の2つを見られるようにする。依頼主は図書館の画像部門の担当者。

1. **時期ごとの色の傾向**: 1889〜1910年代のどの時期に、どの色がよく使われたか。
2. **元絵画との色の違い**: 絵画複製の photochrom と、元になった絵画の色の違い。

成功の姿: 発表で「年代の色の帯」から色を選ぶと該当する photochrom が並び、絵画複製では元絵画と重ねて色の違いを目で確かめられる。

## ゴール / 非ゴール / アンチゴール

- ゴール: 年代別の色の帯 → 色クリック → 該当画像一覧 → 1枚詳細（画像＋パレット）。絵画との重ね合わせ（手動位置合わせ＋透明度）。
- 非ゴール（今回）: legacy 7,658件、位置合わせの保存、自動位置合わせ、アルゴリズム切替 UI。
- アンチゴール: スキャン条件や台紙・カラーチャートの色を「時代の色」として見せてしまうこと。

## データ

- 出典: Zenodo `10.5281/zenodo.24141227`（v1.1）。メタデータ CC0、画像 PDM 1.0。
- 対象: `subset = recatalogued` の 1,952件のみ（e-rara 公開・新スキャンで条件が揃う）。
- 画像: `images-recatalogued-preview.zip`（800px, 250MB）を `data/` に置く（git 管理外）。4K 版は使わない。
- 複数画像の記録（8件）は最初の1枚を使う。
- 表示用画像は e-rara IIIF（`iiif_image_uris` 列）。e-rara の Image API は CORS ヘッダを返さない → ブラウザでピクセルは読めない。色抽出はすべて事前処理。

### スキャンの写り込み（要クロップ）

プレビューを確認した結果、全スキャンに次が写っている:
- 濃いグレーの背景（プリントの外側）
- 下部のカラーチャート（Golden Thread ターゲット）

色抽出の前にプリント部分だけを切り出す。方法: 背景グレーとの差でプリント矩形を検出し、下部チャート帯を除外する。絵画複製の印刷された額縁（金色の枠）はプリントの一部なので残す。

## 色の抽出（決定事項）

1. **共通の色の語彙（コードブック）**: 全画像からピクセルを抜き出してまとめ、CIELAB 空間で k-means（24〜32色）。
2. **画像ごとの色の割合**: 各画像の全ピクセルを最も近いコードブック色に割り当て、割合ベクトルを保存。彩度の低いピクセル（紙・霞）は重みを下げる。
3. **画像ごとのパレット**: 割合ベクトルの上位色をそのまま詳細画面のパレットにする。
4. 年代の帯・色クリックでの絞り込み・詳細パレットは、すべてこの1つの語彙を共有する。

## 年代の扱い（決定事項）

`date_of_publication_or_production_standardised` を使う。
- 単年: その年に割り当て。
- 3年以内の幅（例 `1902/1904`, 138件）: 各年に均等配分（重み 1/n）。これがないと 1902–1903 が空になる。
- 4〜9年の幅: 均等配分（暫定）。
- 10年以上の幅（例 `1891/1914`）: 帯からは外し、別枠「年代不明」帯に置く。
- 各帯に件数 n を表示（1890年 5件、1897年 234件 のように差が大きいため）。

絵画複製（226件）は年代の帯からは既定で外し、切替で含められるようにする。理由: 色がルーベンスやティツィアーノの絵画の色に引っ張られるため。

## 画面

### 画面1: 年代の色の帯

- 1年 = 1本の縦帯。帯の中の色の層の厚み = その年の色の割合（重み付き平均）。
- 色の層をクリック → 下に、その色の割合が高い順の photochrom 一覧（その年に限定）。
- サムネイルクリック → 詳細: IIIF 画像、パレット、タイトル、年代、場所、e-rara へのリンク。

### 画面2: 元絵画との重ね合わせ

- 下に元絵画、上に photochrom。透明度スライダー。
- photochrom をドラッグ（移動）、回転、拡大縮小して手動で合わせる。
- 両者のパレットを横に並べて表示。

## 元絵画の画像

- `subject_title_of_work` の GND ID（40作品）→ Wikidata（P227）→ 画像（P18）で自動取得。試行結果: 9作品で Commons 画像あり。
- 同僚の調査リストが届けば追加する。
- 対応表 `paintings.json`（MMS ID → 絵画画像 URL, 作品名, 作者, 出典）を手で編集できる形にする。

## 技術構成

- 前処理: Python（Pillow, numpy, scikit-learn）、依存管理は uv（ユーザーがセットアップ）。入力は `data/`、出力は `site/data/*.json`。
- 画面: 素の HTML + JavaScript、ビルドなしの静的サイト（`site/`）。
- 公開: GitHub Pages（公開前にユーザーへ確認）。
- 画像はリポジトリに入れない。JSON のみコミット。

## ビルダーに任せること

- コードブックの色数（24〜32の範囲）、サンプリング数、彩度の重みの式。
- プリント矩形検出の具体的なしきい値。
- 画面の細かい見た目。

## 私（Claude）の判断で決めたこと

- 年代幅の配分ルール（3年以内は均等配分、10年以上は「年代不明」帯）。
- 絵画複製を年代の帯から既定で外す。
- 色抽出は共通コードブック方式（ColorThief は使わない）。
- ディレクトリ構成（`data/` は git 管理外、`site/` を公開）。
